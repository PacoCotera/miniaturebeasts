# The Caddy service

The game's Caddy brokers paintings; on the sandbox this small Node service plays it (the sandbox server's web server is also called Caddy, so this one is **the Caddy service**; [station-build.md](../../design/proposals/station-build.md) §2.4 and §4). Plain Node, no dependencies. It ships in the same tested release as the Station page that calls it, under `sandbox/caddy/`, and imports the workbench framework from the release beside it.

The Station page hands over a genome at Grow (`POST /caddy-api/v1/grow`, nothing but a genome and the world is accepted); the service validates it whole against its frame, builds it, hashes it (the genome's SHA-256 in the Grow service's canonical form, which the Station's `sha` and `code` also use), answers done if that set is stored, else queues it. A worker paints one job at a time, journals the queue so a job survives a restart, stores the set by species and hash in a data directory outside the releases, and keeps a daily ledger of calls. A failed call retries at one, five and thirty minutes, then the job fails and the placeholder stands. The page polls its world's jobs every thirty seconds while any mibi waits and on waking, fetches a finished set and swaps it in at the next fresh draw of that mibi.

| Call | Does |
| --- | --- |
| `POST /caddy-api/v1/grow` `{ world, genome, cap?, painter? }` | 400 unless the genome names a registry species, checks against its frame and builds; 200 `done` with the set's URL when stored; 202 `queued` with the job (one job per genome per world) |
| `GET /caddy-api/v1/jobs?world=` | That world's jobs: `queued`, `painting`, `done` (with `set`), `failed`, `capped` (tomorrow) |
| `GET /caddy-api/v1/sets/<species>/<sha16>/<file>` | `station-portrait-300x310.png`, `station-side-300x310.png`, `companion-280x300.png`, `token-48.png`, `manifest.json`; immutable |
| `GET /caddy-api/v1/status` | The painter mode, the queue's counts, today's calls, whether the daily limit is reached, the grow cap, the pinned prompt version |

**Painters.** `mock` (the default): the plain placeholder set rendered here from the genome, warmed so a tester can tell it landed, after `CADDY_MOCK_DELAY` seconds, no call. `real`: `grow/service.py paint --genome … --control twostep --views portrait --out <data>/grow/<job>` (G1: the Grow service's output root, with its call log beside it), the served set copied in; a painting that fails its checks (served plain) is a failed job. Without `GEMINI_API_KEY` in the service's environment the real painter falls back to the mock. `off`: jobs wait queued.

**The daily limit.** `CADDY_CEILING_USD` sets a hard daily limit on paid calls; no page can raise it. At the limit a job waits as `capped` and runs the next day. With no limit set, the service paints with the mock. `CADDY_GROW_CAP` (10) is each world's daily cap; the page may send a lower `cap` with its job, never a higher one. Every real call is in the Grow service's own log under the data directory (`grow/<job>/prompts.json`), its cost in the project's paid-call ledger (`ops/ledger`); the service's private `ledger.json` sums the day.

**Run it.** `node prototypes/caddy/server.mjs` with `CADDY_PORT` (8787), `CADDY_DATA` (the data directory), `CADDY_PAINTER`, `CADDY_CEILING_USD`, `CADDY_GROW_CAP`, `CADDY_MOCK_DELAY`, and for the real painter `GEMINI_API_KEY` and `MB_LEDGER` (the paid-call ledger). `CADDY_CEILING_USD` and `GEMINI_API_KEY` come from a root-only environment file on the sandbox server, never in the repository ([ops/sandbox/install.sh](../../ops/sandbox/install.sh): the unit, the environment file, the proxy route `/caddy-api/*`, Python 3 with Pillow; `deploy.sh` restarts the unit after switching the release). Operator details are in the project's internal operations doc. The calibration batch for the Untuva and the Tuikis stays mock until the owner has seen it.

**Tests.** `node --test prototypes/caddy/tests/*.test.mjs`: refuses a wrong genome, deduplicates by hash and world, serves a stored set and never repaints it, survives a restart (a job caught painting goes again), honours the daily limit and the world's cap (a capped job waits for the next day), retries a failed painter at one, five and thirty minutes and then fails, waits with the painter off. The Station's journey (`prototypes/station/tools/journey.mjs`) runs this service in mock mode beside its static server: the hand-off at Grow, the painting landing at the next fresh draw and not before, the service stopped and restarted with the genome waiting in the outbox under "waiting for the cloud".
