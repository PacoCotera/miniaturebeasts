## Verdict

**FAIL, with fixes.** The structure is sound and needs no redesign. The tree follows the framework: species, chapters in ring order, one gene per trait, locked loci folded into the hub, a copy pair per gene, looks rows before doings rows. Every one of the 16 frames fits the screen (at most 8 chapters, at most 6 traits a chapter). Four things fail the code, though. One mark draws data the framework does not have. One state is missing although it is the most common gene state. Two marks claim a finer grain than the code holds. The wireframes also miss S09's sealed chapter and draw genes of the wrong kind on S03 and S09. Fix the items in "Fixes" below before the art (T-130) or the build (T-71, T-131).

## Fixes

For UI/UX (spec and wireframes) unless marked otherwise:

1. **Add the "one look" state** (kind `only`; `rollOptions` length 1). Mark: the doubled pair, unlit, no notch and no tumbler ticks, so it differs from "copy chosen", which is lit with the notch. ▲▼ refuses the turn as the other refusals do. Bay: both frames the same look, neither veiled. This is the most common configurable state, so it has to be designed, not inferred.
2. **Self-changing: not in the framework.** Until the frames carry it, draw Glow (S03) as an inherited-only doing: closed disc and the line to ×. Basking and Phase sit in sealed chapters, so they never show while shut. Keep the step-mark mark in the key, gated on a frame flag. Framework side (my own follow-up, a frame change that needs a ticket): add `selfChanging: { trigger }` to the Glow, Basking and Phase traits. On Create and the Incubator the step marks are always unlit, because only a partner moves a mark.
3. **Glint per chapter, not per gene.** The code says "new here, never what" per chapter. A glint on one gene would tell the player which trait carries the new look. Put the gold glint on the frosted row (the emblem or the row's first gene) once a row. On the screen, "read it now" stays per chapter as it already is.
4. **Sleeping, two states:** (a) a frosted (unread) chapter shows no gate bar and no dots, because asleep is this pod's state and is unknown until the chapter is read (wireframe 03 leaks it). (b) A pod whose switch is already on shows its dots in a plain lit tone, not `mint`. `mint` means "changed by you" and belongs only to dots the player woke.
5. **Sealed, opened:** with `sealedOpen` (or once the find is in), the row turns into frosted genes and then reads like any doings row: inherited-only, with the line to ×. Use the frame's `findKind` (crystal, pearl, shard) for the find picture. A founder's shut sealed chapter stays shut on the Incubator through ready.
6. **Redraw the wireframes against the data in §2:** S03 Claws inherited-only, Shape all configurable, Glow inherited-only, the clash caption with real S03 names; S09 Movement sealed (tide pearl) with no drums in the tray, Shape all configurable; wireframe 03 with no gate bar, and a real sealed example (or none: S03 has no sealed chapter).
7. **First mark meaning:** "a look new to your field guide" (`p.first`, set at read time), not "no resident has this look". Data: `p.first` per trait.
8. **Wish rule (game designer to choose):** the code stores one pinned look per trait. Either mark a gene whose trait is pinned, or (my recommendation, closer to "a piece of your wish") a gene whose founder shows the pinned look.
9. **Rename the drawing terms** "trunk" and "branch" (for example: frame line, chapter line). The framework uses trunk and branch for catalogue loci, and the ticket's own wording shows the clash of names.
10. **Clash is a set:** rims on every trait `clashTraits` returns (1 to n). The link joins them in tree order, and with one trait there is no link. The caption names real traits. Low priority, see §3.
11. **Build (T-71, T-131):** build the tree from the frame version the genome carries, not the current frame (the same rule as `stampFrameOf`). Every gene's kind comes from the frame row (`kind`, `shapeable`, `override`, `switch`, `chapter.sealed`), never from the trait's chapter name. Today the drums exist only for read chapters (`reviewTraits`); the "read it now" ruling needs unread drums, which is a build change.
12. **Incubator states:** "Ready: every gene known" holds only for a founder without a shut sealed chapter. A crossed bud starts with its forecast-certain chapters known (`childKnownChapters`) and keeps the rest frosted at ready and after. It is not "all frost until it is out".

Framework gaps against the design doc (the code wins, flagged for the game designer): self-changing traits (fix 2), and the chapter name "Legs & tail" in the code against "Legs & Tail" in the doc.
