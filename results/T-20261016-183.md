## What changed

`prototypes/workbench/framework/cross.mjs`:
- **`shedPod(frame, mibi, { rng })`:** the pod a returned mibi's place sheds. It is option (b′), agreed with the game designer on 2026-10-17: a cross of the mibi with itself, drawn by the pod's seeded stream.
  - **`SELF_KINSHIP = 1/8`,** documented in the code as a game rule, not a genetics claim. The draw uses it.
  - **The record keeps the true line:** origin `{ kind: "shed", parents: [d, d], parentIds: [id, id] }`, so pedigree kinship to the parent is ≥ 1/2 and later crosses with relatives are penalised.
  - **Redraw guard:** the pod is redrawn from the same stream, up to 24 times, while it equals its parent or its body does not build. Equality compares values, so a copy written as an allele name or as its number on the blend step counts the same. After 24 draws it returns `null`; this never happened in any measurement.
  - **Refusals:** a parent of another species, or with a locked pair that differs from the frame. A parent on an older frame version is also refused; it must be moved first.
  - **Unchanged rules:** no mutation, no self-changing mark carried, sealed chapters crossed like any others.
- **The cross's draw is now a shared helper** (`drawLoci`). `cross()` keeps its behaviour, and `cross(m, m)` is still refused.

`prototypes/workbench/tests/framework.test.mjs` adds one test over all 16 frames. Each frame has 4 pods and 4 bred parents, with 3 sheds each. The test checks that the pod:
- comes out;
- is the same for the same seed;
- never equals its parent;
- is a whole genome of the frame and builds;
- records parents [m, m];
- takes switch copies only from the parent, and keeps blends within the cross's reach of the parent's value;
- keeps locked pairs;
- has kinship ≥ 1/2 to the parent.

It also checks that carried copies come out doubled between 40% and 75% of the time, and that `cross(m, m)` stays refused.

## Side finding (for the lead; not in this ticket's scope)

**Crosses of two valid pods that do not build:** S08 12/200, S09 9/200, S13 10/200, S16 14/200. All other species: 0/200.

- Each frame's viability check samples named pool alleles. Crossed children land on blend steps between those alleles, which the check never tries.
- The design says a child that cannot be built never exists and the cross is not drawn again. So in these four species, about 5–7% of crosses make nothing.
- This deserves a framework ticket: extend the viability check to crossed children, and lock or bound the culprit loci. The game designer should also say how a failed cross is shown; design/game.md already lists "how a cross that fails is shown" as not designed.
