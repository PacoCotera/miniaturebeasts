## Goal
A shed pod whose parent cannot be found reports `pedigreeKnown: false`, as a cross child does, so the caller falls back to identity instead of trusting kinship 0.
## Inputs
results/review-genome-shed-pod.md. In prototypes/workbench/framework/cross.mjs, `relatedness`'s inner `known` returns true for any origin kind other than "cross" (`g.origin?.kind !== "cross"`), so a pod with origin kind "shed" is always "known". Measured on S01 (the type specimen as the parent, a pod from shedPod with a seeded rng): with the parent resolvable, relatedness(pod, parent) is kinship 0.5, pedigreeKnown true (right); with `lookup = () => null`, it is kinship 0, pedigreeKnown true (wrong; a cross child with the same lookup gives pedigreeKnown false).
## Steps
1. In `relatedness`, treat origin kind "shed" like "cross": its recorded parents (digests, or ids for a record) must all resolve for the pedigree to be known.
2. Add one test: a shed pod, then relatedness with the parent resolvable (pedigreeKnown true, kinship at least 0.5) and with lookup returning null (pedigreeKnown false).
3. Run the workbench tests, `frames --check` and the guard with `; echo exit=$?`; change nothing else.
## Not in scope
When the place sheds the pod; the Station and Companion wiring; the four species whose crosses sometimes do not build (already reported in results/T-20261016-183.md).
## Done when
The test passes and nothing else in the diff changes behaviour.
