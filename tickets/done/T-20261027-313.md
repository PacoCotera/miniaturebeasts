## Goal
The owner (2026-10-27): do not run the full test mountain when code does not change or for documentation; GitHub minutes are not free. Today .github/workflows/site.yml runs every test and three browser journeys (about 21 minutes) on every pull request into main and again on the push to main.
## Lines
1. The push to main assembles and deploys only: the test and journey steps run on pull_request (and workflow_dispatch), not on push to main, since main only receives gated pull requests.
2. Per-step change filters on pull requests (one paths-filter step, or git diff against the base; no new third-party action unless already used): node tests only when prototypes/**, .github/*.mjs or the workflow change; the Station journey only for prototypes/station, face, ui, genome-stamp, caddy, workbench; the test page journey only for prototypes/test, station, exploration, play/src; a docs- or website-only change runs the site assembly and the smoke check only. When in doubt for a path, run.
3. Remove the play page's journey (prototypes/play/tools/journey.mjs) from CI; the play page stays published.
4. No parallel job split.
5. Step and job timeouts sized to the new worst case, each with a one-line comment of its measured time.
## Proof
A docs-only diff and a website-only diff skip every test and journey (show the filter's outputs); a prototypes/station change runs the tests and the Station journey; the workflow YAML parses (actionlint if present, else a YAML parse); public guard.
